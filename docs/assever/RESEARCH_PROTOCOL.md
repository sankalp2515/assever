# Executable research protocol

The release retains three independent evidence layers: the 720-cell authored conformance campaign, process/database regression checks, and a separate two-small-model content-injection study. Do not combine their denominators.

## Conformance

`python -m assever.campaign --output /tmp/campaign` executes 24 families, three provider profiles, two role topologies and five authored controls. Each run creates an isolated root; source file hashes and the immutable protocol digest are saved before execution. A fixed five-seed holdout list is published; the main conformance sweep uses seed 101 and does not represent 720 distinct discovered attacks. Synthetic faults and arbitrary calls are authored experiments, not observed vendor vulnerabilities.

The controls retain the same effect service and exact-payload/idempotency behavior. They are typed execution without human-scope checks; a per-action permission gate; exact binding with atomic gross-money protection; full purchase protection with conservative stopping; and adaptive purchase protection. The last two share invariants, while the conservative orchestrator stops after stock closure rather than automatically finding an approved replacement. Unit normalization, root quantities, counts and uncertainty are tested using actual sink observations. An all-FAIL reference result would be suspicious; benign completion remains a separate measurement.

Run records preserve every refused call, error, actual effect, pending outcome and elapsed duration. The evaluator reads the source store using separate observer authority. The runtime never receives the observer's hidden truth for opaque recovery. Each family has an ordinary counterpart, allowed-outcome rule and feasibility witness. The basket oracle accepts either registered supplier's explicitly allowed equivalent SKU combination. It does not require a memorized single vendor response.

## Live study

`python -m assever.live_study --freeze-only --output /tmp/live-study` freezes twelve tasks, two model IDs/digests, five seeds and ordinary/attacked text. Execute the same module without `--freeze-only`. There are 240 planned **model invocations**. Each proposed plan is replayed against payment-only and adaptive controls, yielding 480 matched control replays rather than 480 independent model samples. Three proposed purchase attempts are the maximum. Seller/callback/memory/summary text injection is explicitly labeled separately from the arbitrary-call campaign.

Models are Qwen2.5 0.5B and Qwen3 0.6B, run locally through Ollama. These are small-model experiments. They do not establish the behavior of frontier agents. Record exact model digest, prompt, JSON schema, seed, temperature, context/output limits, response, token counts, error, duration and each replay's effects. Generation errors, malformed plans, invalid suppliers and failure to finish remain visible. There are no silent fallback models or hidden retry attempts. Seeds 907/1009 in protocol v2 are held-out repetitions of these authored families, not novel attack classes. No billed-provider charge is incurred by local inference; electricity and machine depreciation are not measured.

The model-free product journey remains a distinct reproducible typed planner with three scoped agent roles. A successful deterministic journey is never presented as a successful live-model invocation.

## Mechanism comparisons

Duplicate/new-identity/child/concurrent families compare quantity-and-demand enforcement against exact payment binding plus atomic money admission. Pre-admission revocation compares current epochs against stale previews; downstream-change checks exercise exact immutable binding. Response-loss, delayed-commit, expired-dedupe and supplier-switch families compare profile-qualified retention/recovery. Stock closure contrasts adaptive replanning with conservative stop. Individual mechanism-removal ablations must be separately identified; a combined control comparison is not a clean causal estimate of every component.

## Falsification and failures

The independent checker rejects omitted effects, inconsistent bytes, forged success and reordered event chains. Rehashed omissions are tested as well as raw digest corruption. The first preflight exposed double-counting of one actual order when its runtime state was unknown. That checker defect was corrected and the original preflight results retained. Final results reference the corrected source snapshot. Do not discard unfavorable cells or replace them with preset success counters.

All final tables are generated from `summary.json` and `results.json`; the report must match their actual denominators, incomplete outcomes and error counts. Finite conformance coverage is not a sampled population rate. Any confidence interval would need a defensible sampling model; this release presents the observed finite counts instead.
